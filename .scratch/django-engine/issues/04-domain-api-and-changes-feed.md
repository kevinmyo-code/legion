# The domain API

The twelve Kotlin backend interfaces (`app/.../backend/*Backend.kt`, 112 methods) are the spec.
Read them before writing a view: they were traced, every one, and their shape is uniform enough
that this ticket is one generic viewset plus a short list of exceptions.

## The uniform shape

Every synced table gets, under `/api/<app>/<table>/`:

| Method | Path | Kotlin method it replaces | Semantics |
|---|---|---|---|
| GET | `?since=<epoch_ms>` | `fetchChanged*Since(sinceMs)` | rows with `updated_at >= since`, tombstones included (`deleted_at` non-null), ordered by `updated_at`, capped at 1000 with `next_since` |
| GET | `?active=1` | `fetchActive*()` | rows with `deleted_at is null` |
| PUT | `/<origin_guid>/` | `upsert*(originGuid, fields)` and `uploadMigrated*` | **idempotent**: insert if absent, update if present, 200 either way, returns the row. The `updated_at` touch trigger stamps it |
| DELETE | `/<origin_guid>/` | `softDelete*(originGuid)` | sets `deleted_at`, 204, idempotent |

Timestamps on the wire are ISO-8601 UTC strings, exactly what supabase-kt produced, so the Kotlin
`parseTs` helpers survive. Epoch-ms `since` on the query string because that is what the phone's
cursor stores.

`server/api/synced.py`: `SyncedModelViewSet` implementing the four rows above from a model with
`origin_guid`, `updated_at`, `deleted_at`. `SyncedSerializer` base that refuses unknown fields
(a limb sending a column the server does not know is a version skew, and it says so with a 400
naming the field, never a silent drop).

## Exceptions, each named so nobody generalises them away

| Table | Departure | Endpoint |
|---|---|---|
| `events`, `voice_notes`, `vehicles` | phone upserts by server `id`, creates by `origin_guid` | PUT accepts either key; the `id` form never inserts |
| `events` | occurrence skips | `POST /api/dates/events/<id>/skips/ {date}`, `GET .../skips/` |
| `places` | keyed by `label` | `PUT /api/places/<label>/`, `DELETE` likewise |
| `obd_samples` | append-only batch, count | `POST /api/fleet/obd_samples/batch/ [..]`, `GET .../count/`, `GET ?vehicle=<id>&since=` |
| `conversation_audit` | append-only batch, count | `POST /api/memory/conversation_audit/batch/`, `GET .../count/` |
| `statements`, `receipts`, `ledger_transactions`, `receipt_line_items` | **no PUT, no DELETE.** Written only by ticket 03's gate. GET only | |
| `ingested_files` | GET only | |

## Rules that move from Kotlin to Django, the first four

These were ADR 0042's list. They land here as serializer `validate()` and model `clean()`, with a
test each. The phone keeps its pre-check for the faster message; the server is the check.

1. A measured checklist tick needs a number (`ChecklistController.tick`).
2. A no-schedule checklist is done once a tick exists on any day (`ChecklistDayViewLogic`).
3. A Canvas discussion parent's `submitted_at` does not complete its sub-deadlines (one-today 08).
4. The gate's anchors: ticket 03.

## The schema is the handoff

`manage.py spectacular --file server/openapi.yaml`, committed, regenerated by a test that fails
when the committed file is stale. Ticket 09 codes against this file. Endpoint names, field names
and enum values in it are the contract; changing one is a version bump in the `X-Legion-Api`
response header, and the phone refuses to sync against a major it does not know.
