# The app can say what it can do

Kevin: *"i need to know what the app does, users need a wiki on what the app can do."* The voice
guide lives on GitHub - OUTSIDE the app. Nothing inside answers "what can this thing do", which is
the exact question Kevin asked.

## Build

1. **In-app "What can I do" screen**: the same generated copy `tools/voice_guide_copy.py` holds,
   compiled into the app (codegen a Kotlin object from the same source at build time, or a
   packaged asset regenerated by the same script - either way ONE source, drift impossible by
   construction, same posture as voice_guide.py's drift check). Grouped by domain, searchable,
   and each entry says voice phrase AND where the hands path lives (ticket 27's table is the
   source for the latter).
2. **The user wiki** (`docs/voice.html`): regroup around what a person wants to DO, note the hands
   path per capability, and link it from the app's About row.

## Verification

- Drift between app copy and voice_guide_copy.py fails the build - prove it by test.
- Suite green both ways. On the phone: find "how do I add a fuel stop" in under 20 seconds.
