# Kevin's gaps and how Alfred / AI covers them
Saved Nov 25, 2026 from a voice call with Kevin, to hand to the Legion session later.

## Background (Kevin, on the call)
- The goal is Jarvis: Alfred as the assistant he talks things through with while work happens in the background, connected to his things (car already, later cameras, generated UI like a 3D model of the XJ that Alfred can pull up).
- Feature freeze: no new ideas; finish and ship a working, coherent voice demo. Polish and bug fixes (fillers, head unit gaps) count as demo work.
- Many board issues are ADHD brain-dump ideas for the future, not committed work. They should live in a separate ideas place, off the board.
- Split of testing: AI verifies that things work (send text into Legion, check the tool calls and outputs); Kevin judges the feel (timing, fillers, whether Alfred sounds like a person). Friends testing will find edge cases. iPhone testers via a PWA for now; Android gets a normal app, the launcher is for Kevin only.

## The gaps (Kevin agreed: "that lens for sure")
1. Starts strong, but finishing drags once the novelty fades.
2. Goes wide when the lock-in hits, so ideas get mixed with real work.
3. Verifies by feel more than by proof.

## How AI / Alfred covers them
- **Proof:** automated tests that must pass before a ticket counts as done, so "feels fine" sits on top of evidence. Claude Code can drive these (text in, tool calls and outputs checked).
- **Finishing:** a done rule in Alfred: nothing new starts until the current thing ships. Alfred nags daily with "what's closest to finished?"
- **Going wide:** an idea inbox in Alfred. Every brain dump lands there, never on the board.
- Overall: Alfred becomes Kevin's external executive function.
